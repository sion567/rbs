# 变量语法速查（${{ ... }} 与 ${VAR}）

> 适用于步骤命令、步骤 env、条件字段、工作目录等所有支持替换的文本。
> 设计与实现见：设计文档 §6（变量系统）、`src/variables.rs`。

## 一、取值形态

| 写法 | 来源 | 示例 |
|------|------|------|
| `${{ variables.X }}` | project.yaml 的 `variables.<组名>`（「变量组」下拉选中的那张表；YAML 字段名仍为 `environment`） | 选变量组 prod：`${{ variables.DEPLOY_DIR }}` → `/opt/yudao/prod` |
| `${{ env.X }}` | **前序步骤产出**的变量（前一步往 `workspace/.env` 写 `KEY=VALUE`，步骤成功后引擎自动捕获） | 前一步 `echo VERSION=1.2.0> .env`，后一步 `docker build -t app:${{ env.VERSION }}` |
| `${{ targets.名.字段 }}` | targets.yaml 里指定目标的字段 | `${{ targets.prod.host }}` → `192.168.40.198` |
| `${{ now }}` | **运行启动时刻**（引擎侧生成；一次运行所有步骤同值——备份后缀等场景要求一致性） | `cp app.jar app.jar.${{ now }}` → `app.jar.20261023153045` |
| `${{ now.date }}` / `${{ now.time }}` / `${{ now.iso }}` | 同上的日期 / 时间 / 可读格式 | `20261023` · `153045` · `2026-10-23 15:30:45` |
| `${{ run.id }}` | **本次运行唯一标识**（与控制台日志文件同名，整次运行可追溯） | `echo ${{ run.id }} >> /opt/release.log` |
| `${VAR}` | 步骤产出 env → 环境变量表 → 系统环境变量（依次查找） | `${JAVA_HOME}` |

`targets.名.字段` 支持的字段：`host`、`port`、`user`、`kubeconfig`、`context`、`namespace`、`registry`、`work_root`、`name`。

> **时间戳时区说明**：`now` 系列 = 发版机本地时间。若要以**服务器**时间为准，远端（SSH）步骤里直接用
> `$(date +%Y%m%d%H%M%S)` 即可——命令发到远端 shell 求值。两者可并存：跨步骤一致性用 `${{ now }}`，服务器侧实时取值用 `$(date …)`。

## 二、条件表达式（步骤的「＋条件」字段）

`${{ ... }}` 在**条件字段**里不是取值，而是**判断这一步是否执行**：

```yaml
condition: ${{ env.VERSION != '' }}     # VERSION 非空 → 执行；为空/未产出 → 跳过
condition: ${{ variables.ENABLE_CHECK == '' }}   # 反向判断
```

- 前缀支持 `env.` / `variables.` / `targets.名.字段`
- P0 仅支持**非空检查**（`!= ''` / `== ''`），完整表达式引擎为 P1（§13.3）
- 条件无法解析时按真值执行并打警告（fail-open）

## 三、关键行为

- **执行前一次性替换**（§6.3）：不是运行时动态读。命令可预览、可日志、可审计。
- **未解析的占位符原样保留**：`${{ variables.TYPO }}` 拼错会原样出现在命令里，一眼可见。
- **步骤间传递（P0 约定）**：前一步往 `workspace/.env` 追加 `KEY=VALUE`，引擎在步骤成功后捕获合并；
  后续步骤用 `${{ env.KEY }}` 引用。P1 计划自动捕获命令输出（§6.4）。
- **env 注入优先级**（进入命令进程的顺序，后者被前者覆盖）：
  `步骤 env > 工具 env（tools.yaml / 项目级 tools）> target env > 系统环境变量`。
  JAVA_HOME 这类注入只影响该步骤的子进程，不改系统设置。

## 四、完整示例（yudao-cloud/prod-deploy 风格）

project.yaml：

```yaml
variables:
  dev:  { DEPLOY_DIR: /opt/yudao/dev }
  prod: { DEPLOY_DIR: /opt/yudao/prod }
```

prod-deploy.yaml：

```yaml
name: prod-deploy
target: prod           # 上传/远端执行走 192.168.40.198
environment: prod      # 变量组（YAML 字段名保留 environment）：${{ variables.DEPLOY_DIR }} → /opt/yudao/prod
steps:
  - name: 构建产物
    command: mvn -T 1C clean package -DskipTests
    step_type: exec
  - name: 打包
    command: yudao-server/target/*.jar -> dist/server.zip
    step_type: pack
  - name: 上传（带版本号目录）
    command: dist/server.zip -> ${{ variables.DEPLOY_DIR }}/server.zip
    step_type: upload
  - name: 条件发布
    command: sh ${{ variables.DEPLOY_DIR }}/deploy.sh ${{ env.VERSION }}
    condition: ${{ env.VERSION != '' }}   # 构建产出过版本号才发布
    step_type: exec
```
