# 变量语法速查（${{ ... }} 与 ${VAR}）

> 适用于步骤命令、步骤 env、条件字段、工作目录等所有支持替换的文本。
> 设计与实现见：设计文档 §6（变量系统）、`src/variables.rs`。

## 一、取值形态

| 写法 | 来源 | 示例 |
|------|------|------|
| `${{ variables.X }}` | project.yaml 的 `variables.<组名>`（「变量组」下拉选中的那张表；YAML 字段名仍为 `environment`） | 选变量组 prod：`${{ variables.DEPLOY_DIR }}` → `/opt/yudao/prod` |
| `${{ variables.X \|\| 默认值 }}` | X **未定义**时取默认值（Jinja2 `\| default()` 语义；已定义但为空串仍用空串；默认值可带引号） | `${{ variables.PORT \|\| 8080 }}` → 未定义时展开为 `8080` |
| `${{ env.X }}` | **前序步骤产出**的变量（前一步往 `workspace/.env` 写 `KEY=VALUE`，步骤成功后引擎自动捕获） | 前一步 `echo VERSION=1.2.0> .env`，后一步 `docker build -t app:${{ env.VERSION }}` |
| `${{ targets.名.字段 }}` | targets.yaml 里指定目标的字段 | `${{ targets.prod.host }}` → `192.168.40.198` |
| `${{ now }}` | **运行启动时刻**（引擎侧生成；一次运行所有步骤同值——备份后缀等场景要求一致性） | `cp app.jar app.jar.${{ now }}` → `app.jar.20261023153045` |
| `${{ now.date }}` / `${{ now.time }}` / `${{ now.iso }}` | 同上的日期 / 时间 / 可读格式 | `20261023` · `153045` · `2026-10-23 15:30:45` |
| `${{ run.id }}` | **本次运行唯一标识**（与控制台日志文件同名，整次运行可追溯） | `echo ${{ run.id }} >> /opt/release.log` |
| `${VAR}` | 步骤产出 env → 环境变量表 → 系统环境变量（依次查找） | `${JAVA_HOME}` |

`targets.名.字段` 支持的字段：`host`、`port`、`user`、`kubeconfig`、`context`、`namespace`、`registry`、`work_root`、`name`。

> **时间戳时区说明**：`now` 系列 = 发版机本地时间。若要以**服务器**时间为准，远端（SSH）步骤里直接用
> `$(date +%Y%m%d%H%M%S)` 即可——命令发到远端 shell 求值。两者可并存：跨步骤一致性用 `${{ now }}`，服务器侧实时取值用 `$(date …)`。

## 二、条件表达式（步骤的「＋条件」字段）

`${{ ... }}` 在**条件字段**里不是取值，而是**判断这一步是否执行**：

```yaml
when: ${{ env.VERSION != '' }}          # 非空才执行；为空/未产出 → 跳过
when: ${{ variables.ENV }} == prod      # 等值比较（生产专属步骤与通用流程合到一个流程）
when: ${{ variables.ENV }} != prod      # 不等比较；未定义变量按空串参与比较
when: variables.A == variables.B        # 两侧均可为取值表达式（支持 || 默认值）
creates: node_modules                   # 状态守卫：产物路径已存在 → 跳过本步（重跑秒过）
```

- 字段名 `when` / `condition` 等价（YAML 任写其一）；`creates` 为独立字段
- 比较右侧可为字面量（可带引号）或另一取值表达式；未定义变量按空串参与比较
- 前缀支持 `env.` / `variables.` / `targets.名.字段` / `now` / `run.id`
- 条件无法解析时按真值执行并打警告（fail-open）
- `creates` 路径：本地步骤相对项目目录（支持 `*` 通配）；SSH 步骤为远端路径（相对 = work_root），远端用 `test -e` 判定

## 三、关键行为

- **执行前一次性替换**（§6.3）：不是运行时动态读。命令可预览、可日志、可审计。
- **未解析的占位符原样保留**：`${{ variables.TYPO }}` 拼错会原样出现在命令里，一眼可见。
- **步骤间传递（P0 约定）**：前一步往 `workspace/.env` 追加 `KEY=VALUE`，引擎在步骤成功后捕获合并；
  后续步骤用 `${{ env.KEY }}` 引用。P1 计划自动捕获命令输出（§6.4）。
- **env 注入优先级**（进入命令进程的顺序，后者被前者覆盖）：
  `步骤 env > 工具 env（tools.yaml / 项目级 tools）> target env > 系统环境变量`。
  JAVA_HOME 这类注入只影响该步骤的子进程，不改系统设置。

## 三点五、运行时变量与变更触发（GHA step outputs / Ansible handlers）

**step outputs（运行时变量）**：构建产出的版本号这类"运行中才产生"的值，步骤声明正则捕获：

```yaml
- name: 构建
  command: mvn help:evaluate -Dexpression=project.version -q -DforceStdout
  outputs:
    VER: '^(\S+)$'          # 对 stdout 取首个匹配；有捕获组取组 1，无则整行匹配
- name: 上传
  command: target/app-${{ env.VER }}.jar -> /opt/app.jar   # 后续步骤直接引用
```

- 捕获值与 `workspace/.env` 约定同命名空间（`${{ env.X }}`）；未匹配的键留空并告警
- 提示：命令直接写 `echo VERSION=…` 即可（引擎已包 `cmd /C`），手写 `cmd /C` 嵌套会引入引号残留

**handlers + notify（变更才触发）**：只有真的传了新 artifact 才重启，避免每次跑流程都打断线上：

```yaml
steps:
  - name: 上传
    command: target/app.jar -> /opt/app.jar
    notify: [重启服务]      # 上传内容与远端 sha256 不同（真的传了）才登记
handlers:
  - name: 重启服务
    command: systemctl restart app
```

- creates / when / enabled 跳过、上传 hash 未变更 → 不算变更，handler 不执行
- 主流程成功收尾（含黄灯）才执行；按 handlers 定义顺序；handler 失败 = job 失败

**wait 三模式探测（Compose healthcheck 同款）**：

```yaml
- name: 等服务起来
  step_type: wait
  wait: { mode: tcp,   target: 10.0.0.5:8080 }        # 发版机直连可连 = 就绪
  # wait: { mode: http, target: 'http://10.0.0.5:8080/health', interval_seconds: 3 }
  # wait: { mode: command }                              # 缺省：轮询执行 step.command
```

**工具版本要求（mise 风格，project.yaml）**：运行期自动自检——引擎启动时收集本次用到的工具
（步骤 tool ∪ tools_require），逐个现跑 version_check（未配置的降级为检查 command 是否存在），
以现算版本做门禁对比，偏差零步失败 + 人话报错（tools.yaml 里的 version 只是探测快照，不作数）：

```yaml
tools_require:
  java: ">=21"       # >= > <= < 按数字段比较（缺段补 0）；"22" 前缀匹配 22.x；"22.1.3" 精确
  node: ">=20"
```

- 自检输出进控制台（`[自检] java 21.0.3 ✓`），工具可用性成为运行记录的一部分
- 步骤 `tool` 字段 = 版本选择器（env 注入 + PATH 前置，命令文本不变）；只影响发版机
  本机执行的步骤，SSH 远端步骤在远端 shell 执行

- 版本取自 tools.yaml 的探测结果（首启/⚙ 设置探测写入）；干跑预览会显示每条对比

**pack 打包格式与排除**：格式由**目标扩展名**决定——`.zip` → zip；`.tar.gz` / `.tgz` →
tar+gzip（Linux 惯用；tar 保留可执行权限，Windows 打 zip 到 Linux 解压会丢 +x）。
`target/ -> dist/app.tar.gz --exclude node_modules --exclude *.map`
（排除为 rsync --exclude 语义：字面量 = 目录/文件名分量整棵排除；`*` `?` = 通配匹配相对路径与文件名。
目录源条目带目录名根：`dist -> app.tar.gz` 里面是 `dist/...`，同 `tar -czf` / `zip -r` 习惯；
**源以 `/.` 结尾 = `tar -C dist .` 语义**：`dist/. -> app.tar.gz` 条目不带目录根，解包
`tar -xzf app.tar.gz -C /opt/app` 直接铺文件；zip / tar.gz 同一语义。
单文件 / 通配源条目为裸文件名）

## 四、完整示例（yudao-cloud/prod-deploy 风格）

project.yaml：

```yaml
variables:
  dev:  { DEPLOY_DIR: /opt/yudao/dev }
  prod: { DEPLOY_DIR: /opt/yudao/prod }
```

prod-deploy.yaml：

```yaml
name: prod-deploy
target: prod           # 上传/远端执行走 192.168.40.198
environment: prod      # 变量组（YAML 字段名保留 environment）：${{ variables.DEPLOY_DIR }} → /opt/yudao/prod
steps:
  - name: 构建产物
    command: mvn -T 1C clean package -DskipTests
    step_type: exec
  - name: 打包
    command: yudao-server/target/*.jar -> dist/server.zip
    step_type: pack
  - name: 上传（带版本号目录）
    command: dist/server.zip -> ${{ variables.DEPLOY_DIR }}/server.zip
    step_type: upload
  - name: 条件发布
    command: sh ${{ variables.DEPLOY_DIR }}/deploy.sh ${{ env.VERSION }}
    condition: ${{ env.VERSION != '' }}   # 构建产出过版本号才发布
    step_type: exec
```
