# 命令与工具速查（build.yaml 步骤常用命令）

> 定位：写步骤 `command` 时的命令参考——每条给**实例**（抄即用）+ **参数说明**。
> 提示：编辑器里输入命令有**自动补全**——命令骨架、已知命令空格后的逐参数提示
> （mysqldump / curl / mvn / grep 等）、`${{ variables.X }}` 变量 / targets 字段 / 内置变量；
> ↑↓ 选择 / Tab 上屏 / Esc 关闭。本文件是逐参数完整版。
> 变量替换（`${{ ... }}` / `${VAR}`）与步骤字段（when / creates / outputs / wait / secret_env / tool）
> 见 [变量速查.md](变量速查.md)；长任务（nohup + wait 轮询）配方见 [长任务配方.md](长任务配方.md)。

## 执行位置约定（先读这个）

| 标记 | 谁执行 | Shell | 语法注意 |
|------|--------|-------|----------|
| 【本地】 | 发版机 Windows（引擎包 `cmd /C`） | cmd | `&&` `\|` `>` `>>` 可用；变量写 `%VAR%`（cmd 展开）或 `${{ }}`（RBS 替换）；**单引号、`$VAR`、`$()` 不可用** |
| 【远端】 | SSH 步骤发到远端 Linux | 登录 shell | bash 语法全量可用（`$VAR`、`$()`、单引号等） |

- cmd 会自动补扩展名（`mvn` → `mvn.cmd`），但**无扩展名的 shell 脚本不行**——Windows 本地跑 Gradle
  要写 `gradlew.bat`（`gradlew` 本体是 sh 脚本）；远端 Linux 写 `./gradlew`。
- 命令找不到 / 版本不对 → `tool:` 字段绑定工具（tools.yaml 登记路径 + env 注入 + PATH 前置），
  `tools_require` 做版本门禁（⚙ 设置 → 🔧 工具管理）。
- 首次连接类命令（装包、下载 JDK）建议放 `preconditions` 或一次性初始化流程，别放每次发版主流程。

## 一、Linux 常用命令【远端】

### 文件与目录

```bash
ls -lah /opt/app                              # 长格式 + 隐藏文件 + 人读大小
cp -a app.jar backup/app-${{ now }}.jar       # 归档复制（保留权限/时间戳，递归）
mkdir -p /opt/app/backup                      # 多级创建，已存在不报错
ln -sfn /opt/releases/app-1.2.3 /opt/app      # 软链指向新版本（发布切换惯用）
find /opt/backup -name "app-*.jar" -mtime +7 -delete      # 删 7 天前的备份
find /opt -name "*.log" -size +100M           # 找大文件
chmod +x deploy.sh && chown -R app:app /opt/app
```

- `cp -a`：保留权限/属主/时间戳递归复制（备份场景首选）；`-r` 仅递归
- `ln -sfn 新目标 链接名`：`-s` 软链、`-f` 已存在先删、`-n` 把指向目录的链接当文件替换（原子切换的关键）
- `find 路径 -name 通配 -mtime +N 天 -size +N M -delete / -exec 命令 {} \;`
- `rm -rf` 属危险命令：RBS 预览与执行前会 ⚠ 提醒；路径写全，别用变量拼根目录

### 查看与文本处理

```bash
tail -n 100 app.log                           # 末 100 行
tail -f app.log                               # 跟踪新增（Ctrl+C 退出）
grep -c ERROR app.log                         # 计数
grep -in "timeout" app.log                    # 忽略大小写 + 行号
ps -ef | grep java | grep -v grep             # 查进程（-v 剔除 grep 自身）
sed -i 's/8080/8081/g' config.yml             # 就地替换（g = 全局）
awk -F: '{print $1}' /etc/passwd              # 按冒号切列取第 1 列
du -sh /opt/* | sort -rh | head -5            # 各目录占用 Top5
wc -l app.log                                 # 行数
```

- `grep`：`-i` 忽略大小写、`-n` 行号、`-v` 反选、`-c` 计数、`-r` 递归目录、`-E` 扩展正则、
  `-A2 / -B2 / -C2` 命中行的后 / 前 / 上下 2 行
- `sed -i 's/旧/新/g'`：`-i` 写回原文件（不加则只打印）；分隔符可换 `s|a|b|g`
- `awk -F分隔符 '{print $N}'`：按列取值；`$NF` = 最后一列
- `du -sh`：`-s` 汇总、`-h` 人读；`df -h` 看磁盘余量；`free -h` 看内存

### 进程

```bash
pgrep -f app.jar                              # 按命令行片段查 PID
pkill -f app.jar                              # 按命令行片段杀（比 killall 稳）
kill -9 12345                                 # 强杀指定 PID
nohup /opt/app/start.sh > app.out 2>&1 &      # 后台起飞，SSH 断开不连带（长任务配方）
```

- `pgrep/pkill -f`：匹配**完整命令行**（不带 `-f` 只匹配进程名）；`pkill` 返回 0 = 杀到了
- `nohup … > 输出 2>&1 &`：`2>&1` 把 stderr 并入 stdout、结尾 `&` 后台——
  配合 `wait` 步骤轮询状态文件做长任务，配方见 长任务配方.md

### 网络与探测

```bash
ss -tlnp | grep 8080                          # 谁在监听 8080
lsof -i:8080                                  # 谁占着端口（含进程命令行；需 lsof 包）
curl -sf http://127.0.0.1:8080/health         # 健康检查（-f：非 2xx 返回非零）
curl -s -X POST -H "Content-Type: application/json" -d '{"k":"v"}' http://host/api
curl -sk https://host/health                  # 自签证书跳过校验
wget -q -O /tmp/app.jar http://host/app.jar   # 下载
ping -c 3 10.0.0.5                            # 发 3 个包
```

- `ss -tlnp`：`-t` TCP、`-l` 监听、`-n` 不解析域名、`-p` 显示进程（老系统用 `netstat -tlnp`）
- `curl`：`-s` 静默、`-f` HTTP≥400 时返回码非零（脚本判断成败的关键）、`-o` 写文件、
  `-m 10` 总超时秒、`--connect-timeout 3` 连接超时；RBS `wait` 的 http 模式不支持 https，
  要探测 https 就用命令模式 `curl -skf`
- `ssh -p 2222 user@host` / `scp -P 2222 文件 user@host:/dst`：大写 `-P` 指端口（ssh 小写 `-p`）。
  注意 RBS 的 upload / download 步骤已覆盖主链路，这些用于远端侧中转或手工调试

### 传输与同步（rsync）

```bash
rsync -avz dist/ user@host:/opt/app/          # 增量同步（首轮全量后只传差异，很快）
rsync -avn dist/ user@host:/opt/app/          # -n 干跑：先看会传什么再真跑
rsync -avz --delete dist/ /opt/app/           # 镜像同步：目标多出来的文件删掉（想清楚再 --delete）
```

- `-a` 递归 + 保留权限/时间戳（几乎必带）、`-v` 详情、`-z` 压缩传输、`--exclude 模式` 排除
- **尾随斜杠有语义**：`dist/` 传"内容"不带 dist 根；`dist` 会在目标下多套一层 dist——
  与 pack 步骤 `源/.` 的 `tar -C` 语义对应
- 大量小文件先 `pack` 成单包再传仍是最快的；rsync 强在**反复同步的增量**场景

### 防火墙开端口（新服务不通先想它）

```bash
firewall-cmd --permanent --add-port=8080/tcp && firewall-cmd --reload   # firewalld（CentOS 系）
firewall-cmd --list-ports                     # 看已开端口
ufw allow 8080/tcp && ufw status              # ufw（Ubuntu 系）
```

- `--permanent` 不加 = 只对本次运行生效，reload 后丢失；加了 permanent **还要 reload** 才生效
- 本机防火墙通了仍不通 → 云服务器还有**安全组**一层（控制台配），排查顺序：服务监听
  （`ss -tlnp`）→ 本机防火墙 → 安全组

### SSH 公钥免密（RBS 目标用 key 认证的前置）

```bash
ssh-keygen -t ed25519                         # 生成密钥对（一路回车；-C 备注区分用途）
ssh-copy-id -p 2222 user@host                 # 公钥装到目标机（Windows 无此命令：手动追加 .pub 内容）
chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys   # 权限不对 sshd 会直接拒用
```

- 实质 = 把本机 `~/.ssh/id_ed25519.pub` 内容追加进目标机 `authorized_keys`，理解了手动装也不难
- 免密后 RBS 目标认证选密钥：russh 要求 **OpenSSH 格式**私钥（PuTTY PPK 先用 puttygen 转换，
  见 README「认证与安全」）

### 定时任务（crontab）

```bash
crontab -l                                    # 看当前用户的定时任务
crontab -e                                    # 编辑
(crontab -l; echo "0 2 * * * /opt/app/backup.sh >> /var/log/backup.log 2>&1") | crontab -
```

- 五段 = 分 时 日 月 周（上面例：每天 02:00）；`>> 日志 2>&1` 把输出留痕，排障靠它
- `| crontab -` 是**整体覆盖**——追加要 `(crontab -l; echo 新任务) | crontab -`，直接
  `echo | crontab -` 会把原有任务清掉

### 环境变量与查找

```bash
which mvn java                                # 命令实际走的路径（排"为什么版本不对"第一步）
env | grep -i mysql                           # 查环境变量（验证 secret_env 注入结果）
export JAVA_HOME=/usr/lib/jvm/jdk-21          # 只活当前 shell
source /opt/app/env.sh                        # 读脚本里的 export 到当前 shell
```

- **SSH 步骤每一步都是新 shell**：上一步 `export` 的变量下一步不存在——要跨步骤传值用
  RBS 的 `outputs` / `.env` 约定（见 变量速查.md），不要指望 export

## 二、Shell 片段与管道【远端】

写 `wait` 探测命令、发布脚本时的最小语法集：

```bash
[ -f /opt/app/app.jar ] && echo 在 || echo 缺          # 文件判断（-d 目录、-e 存在即可）
[ -z "$TAG" ] && TAG=v0.0.0                            # 空串则给默认（-n = 非空才真）
VER=${TAG:-v0.0.0}                                     # 变量默认值展开（未定义/空都取默认）
NOW=$(date +%Y%m%d%H%M%S)                              # 命令替换：拿命令输出当值用
if [ $? -eq 0 ]; then echo 上条成功; fi                 # 上一条命令的退出码
ls -t /opt/backup/app-*.jar | tail -n +6 | xargs -r rm # 只留最近 5 份（示范工程④同款）
echo "$(date '+%F %T') 发版" | tee -a /opt/release.log # 打屏同时落文件（-a 追加）
cut -d, -f2 data.csv                                   # 按逗号取第 2 列
sort 记录.txt | uniq -c | sort -rn | head -5           # 频次 Top5
for f in /opt/backup/app-*.jar; do sha256sum "$f"; done             # 一行循环
```

- **判断符别混**：字符串 `=` `!=`、空/非空 `-z` `-n`、文件 `-f` `-d` `-e`、
  数字 `-eq` `-ne` `-gt` `-lt`（数字比较**不是** `>` `<`——那是重定向/比较文本）
- `xargs -r`：输入为空就不执行（不带 `-r`，空输入也会跑一次 `rm`）
- `2>/dev/null`：吞掉报错输出；`2>&1` 把 stderr 并进 stdout
- `$?` 与 `&&` `||` 组合是脚本判断成败的全部：`命令 && 成功走这 || 失败走这`

**wait command 探测脚本模板**（长任务配方，`fail_exit_code: 2`）：

```bash
s=$(cat /opt/demo/backup/status 2>/dev/null || echo running)
[ "$s" = success ] && exit 0        # 就绪 → wait 通过
[ "$s" = failed ]  && exit 2        # 任务已死 → 立即失败，不烧完超时
exit 1                              # 还在跑 → 继续按 interval 轮询
```

## 三、systemctl 与日志【远端】

```bash
systemctl restart app                         # 重启（start / stop / status 同型）
systemctl enable --now app                    # 开机自启 + 立即启动（一条顶两条）
systemctl is-active --quiet app && echo 存活  # 脚本判活（--quiet 不输出，只看退出码）
systemctl daemon-reload                       # 改过 *.service 文件后先执行这条
journalctl -u app -n 100                      # 该服务最近 100 行
journalctl -u app -f --since "10 min ago"     # 跟踪日志（-p err 只看错误）
```

- `systemctl`：`enable` 开机自启、`disable` 取消；`is-active --quiet` 的退出码就是判活结果，
  适合接 `preconditions` 或 `when` 思路的 shell 判断
- `journalctl -u 服务名`：`-f` 跟随、`-n N` 最近 N 行、`--since`/`--until` 时间窗、
  `-p err` 起的级别过滤

> RBS 配合：重启步骤常配 `retry`（服务起太慢）+ `wait` tcp/http 探活；首次部署服务不存在时
> `systemctl stop` 加 `continue_on_error: true` 只黄灯不拦（示范工程 ④）。

## 四、包管理【远端】

### apt（Debian / Ubuntu）

```bash
apt update                                    # 刷新索引（装包前先跑）
apt install -y curl jq                        # -y 免交互确认
apt remove -y curl                            # 卸载（purge 连配置一起删）
apt list --installed 2>/dev/null | grep mysql # 查已装版本
```

### yum / dnf（CentOS / RHEL / 麒麟等）

```bash
yum install -y curl jq                        # dnf 同型（新系统首选 dnf）
yum list installed | grep mysql
rpm -q mysql-server                           # 查单个包版本
```

- 共同套路：装包前 `update`（apt）/ 直接装（yum 自带索引刷新节奏不同）；`-y` 免交互必须带
  （SSH 非交互终端没有"确认"机会，会直接卡死到超时）
- 放进流程时配 `creates:`（如 `creates: /usr/bin/jq`）守卫——装过就跳过，重跑秒过

## 五、压缩与解包

```bash
tar -czf app.tar.gz -C dist .                 # 打包（-C 进目录再打，条目不带 dist/ 前缀）
tar -xzf app.tar.gz -C /opt/app               # 解包到指定目录（目录不存在先 mkdir -p）
tar -tzf app.tar.gz | head                    # 只看包里有什么，不解
zip -r app.zip dist --exclude "*.map"         # 远端手工打包（RBS pack 步骤已内置 zip/tar.gz）
unzip -o app.zip -d /opt/app                  # -o 覆盖不问（非交互必须）
7z a -t7z backup/db.7z backup/*.sql           # 7z 压缩（tool: 7z 绑定，示范工程 ⑤）
7z x backup/db.7z -o/opt/restore -p密码       # 解压（-o 后紧跟目录不加空格）
```

- `tar -c` 建、`-x` 解、`-t` 看；`-z` gzip（`.tar.gz`）、`-f` 文件名（几乎总在最后跟包名）、
  `-C` 切换目标目录、`--exclude 模式` 排除
- **权限注意**：Windows 侧打 zip 传 Linux 解压会丢可执行位；传带 `.sh`/二进制的包用
  `tar.gz`（RBS pack 的 tar.gz 保留 +x），或解压后补 `chmod +x`
- `7z a` 添加压缩（`-t7z` 格式、`-mx=9` 最高压缩率、`-p` 加密）；`7z x` 带目录结构解压、
  `7z e` 全部铺平——配 `tool: 7z` 使用

## 六、Windows 本地常用命令【本地 cmd】

本地步骤在发版机 Windows 上由 `cmd /C` 执行（示范工程大量 `cmd /C …` 写法即此）：

```bat
dir /B target\*.jar                           # 列文件名（/B 裸名；配 outputs 捕获产物名）
copy /Y target\app.jar backup\                # /Y 覆盖不问（非交互必带）
xcopy dist\* release\ /E /I /Y                # 递归复制（/E 含空目录 /I 目标是目录）
robocopy dist release /MIR /XD node_modules   # 镜像同步（/XD 排除目录 /XF 排除文件）
mklink /J app D:\releases\app-1.2.3           # 目录 junction（免管理员；/D 真软链要管理员）
del /Q backup\*.sql                           # 删文件（/Q 免确认）；rmdir /S /Q dist 删整树
tasklist | findstr java                       # 查进程（findstr ≈ grep）
taskkill /PID 1234 /F                         # 强杀进程（/IM java.exe /F 按映像名杀一片）
netstat -ano | findstr :8080                  # 查端口占用（末列 = PID → taskkill）
sc query demo-app                             # 查 Windows 服务状态
sc stop demo-app                              # 服务启停（start 同型；需管理员）
netsh advfirewall firewall add rule name="app-8080" dir=in action=allow protocol=TCP localport=8080
                                              # 防火墙开端口（需管理员；删规则 delete rule name=…）
schtasks /Create /SC DAILY /ST 02:00 /TN 备份 /TR D:\app\backup.bat   # 计划任务（crontab 对应物）
schtasks /Run /TN 备份                        # 手动触发一次（调试用）；/F 覆盖同名任务
where mvn                                     # 命令实际路径（cmd 版 which）
curl.exe -sf http://127.0.0.1:8080/health     # Win10 1803+ 自带真 curl（写 .exe 防别名歧义）
certutil -hashfile app.zip SHA256             # 算哈希（对 upload 步骤 sha256 校验排障）
set JAVA_HOME=C:\jdk-21                       # 本命令内临时环境变量（echo %JAVA_HOME% 验证）
powershell -Command "Get-Content app.log -Tail 100"   # 逃生舱：复杂逻辑借 PowerShell
```

- **robocopy 退出码陷阱**：`0-7 都算成功`（1 = 复制了文件），直接用会被 RBS 按非零判失败——
  收尾接 `& if %ERRORLEVEL% GEQ 8 (exit /B 1) else (exit /B 0)`
- cmd 变量是 `%VAR%`（Linux 的 `$VAR` 不可用）；引号内转义用 `\"`；管道/重定向/`&&` 与 bash 同名同义
- `mklink /J`（junction）**不需要管理员**且跨本地卷，发布"软链切换"在 Windows 上的对应物；
  `/D` 真符号链接才需要管理员
- `schtasks /TR` 带参数时整段要引号包住并转义内部引号（`/TR "\"D:\app\x.bat\" arg"`）；改完用
  `schtasks /Run` 手动触发验证一遍
- `curl` 在 cmd 里可能被 PowerShell 别名坑（旧 ps 的 curl 是 Invoke-WebRequest）——
  本地步骤是 cmd 没这个问题，但显式写 `curl.exe` 最稳
- 复杂逻辑别硬写 cmd 一行串：借 `powershell -Command`，或把脚本放工程里 `脚本.bat` / `脚本.ps1` 调用

## 七、git【本地 workspace】

```bash
git clone --depth 1 https://gitee.com/x/demo.git demo    # 浅克隆（只要最新版）
git pull --ff-only                            # 只快进合并（有分叉直接失败，不悄悄合）
git status -s                                 # 短格式状态
git log --oneline -5                          # 最近 5 条
git switch develop                            # 切分支（checkout 同效）
git tag -a v1.2.0 -m "发版"                   # 打附注标签
git add -A && git commit -m "x" && git push origin HEAD
```

- `clone --depth 1`：只拉最新一层，大仓库快很多（代价：没有历史，需要时 `git fetch --unshallow`）
- `pull --ff-only`：远端有强制推送 / 本地有提交时直接报错而非自动合并——发版流程要的是
  "确定拿到哪个版本"，示范工程 ① 即此写法
- RBS 配合：克隆步骤 `creates: demo/.git` 守卫（克隆过秒过）；工作目录用步骤 `working_dir: demo`

## 八、Maven【本地】

```bash
mvn -B clean package -DskipTests
mvn -T 1C clean package -P prod -DskipTests              # 并行 + 指定 profile
mvn -pl yudao-server -am clean package -DskipTests       # 只构建指定模块及其依赖
mvn help:evaluate -Dexpression=project.version -q -DforceStdout   # 取版本号（配 outputs）
mvn dependency:tree -Dincludes=com.mysql:mysql-connector-j         # 查依赖来源
mvn clean deploy -DskipTests                             # 发私服
```

| 参数 | 说明 |
|------|------|
| `-B` | 批处理模式：关进度条彩色输出，日志干净（CI / 工具环境标配） |
| `-q` | 只输出 ERROR 与必要结果；配 `outputs` 正则捕获 stdout 时用 |
| `-T 1C` | 每核 1 线程并行构建模块（多模块项目提速明显） |
| `-P 名` | 激活 pom 里的 profile（dev / prod 差异化打包） |
| `-D键=值` | 传系统属性。`-DskipTests` 编译测试类但不跑；`-Dmaven.test.skip=true` 连编译都跳 |
| `-U` | 强制刷新 SNAPSHOT 依赖（私服上 SNAPSHOT 更新了但本地缓存旧时） |
| `-o` | 离线模式：只吃本地仓库（内网 / 已拉过依赖时快） |
| `-pl 模块 -am` | `-pl` 只构建该模块；`-am` 连它的上游依赖一起建（微服务改一个服务时用） |
| `-s 路径` | 指定 settings.xml（多私服 / 镜像源隔离） |
| `-Dmaven.repo.local=路径` | 指定本地仓库（多 JDK / 多项目隔离，或挪出 C 盘） |
| `help:evaluate -Dexpression=… -DforceStdout` | 取任意 pom 属性；`-DforceStdout` 输出裸值，`outputs: { VER: '(\S+)$' }` 即可捕获 |

> RBS 配合：`timeout: 1800`（首次拉依赖慢，默认超时会误杀）、`creates: target/*.jar`
> （产物在就跳过，配作业级 retry 只补失败步骤）、`tools_require: { java: ">=21" }` 版本门禁。

## 九、Gradle【本地 / 远端】

```bash
gradlew.bat clean bootJar --no-daemon         # Windows 本地（cmd 下必须带 .bat）
./gradlew clean bootJar --no-daemon           # 远端 Linux / mac
gradlew.bat build -x test                     # 跳过 test 任务
gradlew.bat bootJar -Penv=prod                # 传项目属性（build.gradle 里 project.env）
gradlew.bat --refresh-dependencies build      # 强刷依赖
```

- `gradlew`（wrapper）：按工程 `gradle/wrapper/gradle-wrapper.properties` 钉死 Gradle 版本，
  **永远优先于全局 `gradle`**——换机零配置
- `bootJar`：Spring Boot 可执行 jar（`build` = 全量含 test，发版通常 `clean bootJar -x test`）
- `-x 任务名`：排除任务（`-x test`、`-x spotlessCheck`）
- `-P名=值`：传构建属性（区别于 `-D` 的 JVM 系统属性）
- `--no-daemon`：不驻留后台 daemon 进程（构建工具环境推荐；daemon 在 CI 类环境会占内存、
  留孤儿进程——RBS 有进程树清理，但省资源仍建议关）
- `-p 目录`：指定项目目录（多仓库结构时）

## 十、前端 Node（pnpm / npm）【本地】

```bash
corepack enable && corepack prepare pnpm@latest --activate   # 按 package.json 的 packageManager 钉版本
pnpm install --frozen-lockfile                # CI 标准装依赖
pnpm run build                                # 执行 package.json scripts.build
npm ci                                        # npm 项目的干净安装（按 lock 精确装，先删 node_modules）
npm run build
npm config get registry                       # 查源（淘宝源 registry.npmmirror.com）
```

- `--frozen-lockfile`：lockfile 与 package.json 不一致**直接失败**而不是自动改——保证构建可重现
- `npm ci` vs `npm install`：ci 严格按 lock 装、更快、绝不改 lockfile（CI 标配）
- `corepack`：Node 自带的包管理器版本钉子（示范工程 yudao-admin-uniapp 即此模式）；
  工程没写 `packageManager` 字段时才需要 `pnpm install -g pnpm`
- RBS 配合：装依赖步 `creates: node_modules`（装过跳过）；构建步 `creates: dist`

## 十一、Java 运行时与排障【本地 / 远端】

启动参数（远端 systemd 单元、本地调试都适用）：

```bash
java -Xms512m -Xmx2g -jar app.jar --spring.profiles.active=prod --server.port=8080
java -Dfile.encoding=UTF-8 -Duser.timezone=Asia/Shanghai -jar app.jar
jps -l                                        # 列 java 进程 + 主类/jar 名（cmd 同款可用）
jstack <pid> > /tmp/stack.txt                 # 线程栈快照（卡死 / 死锁排查）
jmap -histo:live <pid> | head -20             # 对象直方图（内存涨排查）
jar tf app.jar | head                         # 看 jar 内容不解包
keytool -importcert -alias internal-ca -file ca.cer -keystore trust.jks -storepass changeit -noprompt
```

- **参数位置别错**：JVM 参数（`-Xmx`、`-Dxxx`）必须在 `-jar` **前面**；jar 名后面的
  `--xxx` 是程序参数（Spring Boot 解析）——写反了不生效还找不到原因
- `-Xms` / `-Xmx`：初始 / 最大堆（生产两者设同值，避免动态扩缩抖动）；容器里配 `-XX:MaxRAMPercentage=75`
- `-Dfile.encoding`：日志乱码第一嫌疑（Windows 发版机跑 bat 启动尤其常见）；
  `-Duser.timezone` 修复"日志时间差 8 小时"
- `jps -l`：免 ps + grep 猜进程；`jstack` 需要同用户或管理员执行
- `keytool`：导入自签 CA / 中间证书到信任库（`-storepass` 默认库口令 `changeit`、
  `-noprompt` 免交互确认）；`-list -v -keystore trust.jks` 反查已装条目

## 十二、Docker【本地】

```bash
docker build -t registry.internal:5000/app:${{ env.VER }} .
docker build -f Dockerfile.prod --build-arg APP_ENV=prod -t app:${{ env.VER }} .
docker push registry.internal:5000/app:${{ env.VER }}        # 推镜像（login 一次后免密）
docker save -o app.tar registry/app:${{ env.VER }}           # 导出离线包（内网无 registry 时）
docker load -i app.tar                                       # 目标机导入（SSH 步骤远端执行）
docker logs -f --tail=100 容器名                              # 跟日志
docker images / docker ps -a / docker rmi 镜像:tag
docker login registry.internal:5000 -u user                  # 密码交互输入，别进命令行
```

- `-t 名:tag`：镜像全名（私服地址/项目/名字:版本）；`-f` 指定 Dockerfile；`--build-arg`
  传 Dockerfile 里 `ARG` 声明的构建参数
- `save / load`：`save` 导出的 tar 配 RBS `upload` 步骤传到目标机再 `load`——
  没有 registry 的内网发布链路
- 构建慢 → 层缓存按顺序命中：**常变的内容（源码 COPY）放 Dockerfile 靠后**，
  依赖安装（`COPY pom.xml` + `mvn dependency:go-offline`）放前面
- 版本号来源：上游 `outputs` 捕获（`mvn help:evaluate …`）→ `${{ env.VER }}`，
  不要手写 latest

## 十三、Kubernetes（kubectl）【本地 · k8s 目标】

```bash
kubectl apply -f deploy.yaml                  # k8s-apply 步骤；-n 指命名空间
kubectl apply -f k8s/ -n ${{ variables.NAMESPACE }}        # 目录全量应用
kubectl get pods -n demo-prod -o wide         # 列表（-w 持续 watch）
kubectl logs -f --tail=100 pod名 -c 容器名    # 跟日志（多容器要 -c）
kubectl describe pod pod名                    # 排查拉不起 / 镜像拉取失败 / 挂载错误
kubectl rollout restart deployment/app        # 滚动重启（改了 ConfigMap 后）
kubectl rollout status deployment/app --timeout=120s       # 等滚动完成
kubectl rollout undo deployment/app           # 回滚到上一版
kubectl set image deployment/app app=registry/app:${{ env.VER }}    # 只改镜像触发滚动
kubectl scale deployment/app --replicas=3
kubectl exec -it pod名 -- sh                  # 进容器
kubectl cp pod名:/path/file ./file            # 容器拷文件
kubectl config get-contexts                   # 查 kubeconfig 里有哪些集群上下文
```

- `-n 命名空间`：省略时用 context 默认空间；`-o wide|json|yaml` 输出格式
- `rollout` 家族：`restart`（重建 Pod，配置变更后用）、`status --timeout`（脚本等完成）、
  `undo`（回滚上一 Revision）、`history`（看版本）
- `apply -f` 幂等：存在即更新、不存在创建（对比 `create` 存在即报错）
- RBS 配合：目标类型选 **k8s**（kubeconfig / context / namespace 存目标里，步骤里用
  `${{ targets.名.* }}` 引用）；`k8s-apply` 步骤在发版本机跑 kubectl，`KUBECONFIG`
  由引擎自动注入——命令里不用手动指定。`get logs describe` 这类排障命令放普通
  exec 步骤（同目标时 KUBECONFIG 同样注入）

## 十四、Nginx【远端】

```bash
nginx -t                                      # 改完配置必跑：测语法（找的是哪行错）
nginx -s reload                               # 热加载（不断现有连接）
nginx -s quit                                 # 优雅停（处理完当前请求）；-s stop 立即停
nginx -s reopen                               # 重开日志文件（日志切割用）
systemctl reload nginx                        # apt/yum 装的用 systemd 管理走这条
tail -f /var/log/nginx/error.log              # 502 / 504 第一现场
tail -f /var/log/nginx/access.log             # 请求流水（$status 看码）
```

- `nginx -s 信号` 需要找得到 pid 文件（编译安装默认）；包管理器装的一律 `systemctl`——
  两者混用报"找不到 pid / 进程已存在"就是这么来的
- reload 前必 `-t`：配置有语法错 reload 会失败且**保持旧配置在跑**，不会白屏但要记得回头看返回码
- 502 排查顺序：`error.log` 里 upstream 报什么 → 后端进程活着吗（`ss -tlnp | grep 端口`）
  → SELinux / 防火墙

## 十五、MySQL（mysql / mysqldump）【本地客户端 → 远程库】

```bash
mysql -h ${{ variables.DB_HOST }} -P 3306 -u root -D app_db -e "SELECT COUNT(*) FROM t_order;"
mysql -h ${{ variables.DB_HOST }} -P 3306 -u root app_db < backup/mysql-20261031.sql   # 导入恢复
mysql --login-path=prod -e "SHOW TABLES;"     # mysql_config_editor 存过的免密路径

mysqldump -h ${{ variables.DB_HOST }} -P ${{ variables.DB_PORT }} -u ${{ variables.DB_USER }} \
  --single-transaction --routines --triggers --events \
  ${{ variables.DB_NAME }} > backup/mysql-${{ now.date }}.sql          # 全量备份

mysqldump ... --no-data ${{ variables.DB_NAME }} > schema.sql          # 只导表结构
mysqldump ... --where="created_at >= '2026-10-01'" app_db t_order      # 条件导出单表
```

| 参数 | 说明 |
|------|------|
| `-h` / `-P` | 主机 / 端口。**MySQL 端口是大写 `-P`**（区别于 pg 的小写 `-p`） |
| `-u` / `-p` | 用户 / 密码。`-p` 单独写 = 交互输密码；**严禁 `-p密码` 连写**（进程列表可见）——用 `secret_env` 注入 `MYSQL_PWD` |
| `-D 库名` | 默认数据库（`-e` 执行 SQL 时不用在语句里写库前缀） |
| `-e "SQL"` | 执行单条 SQL 后退出（`-t` 表格化输出） |
| `--single-transaction | InnoDB 一致性快照备份，**不锁表**，生产必备 |
| `--routines --triggers --events` | 存储过程 / 触发器 / 事件（默认不含 routines 与 events） |
| `--databases db1 db2` | 备份多库且带 `CREATE DATABASE` 语句；不带则只备表数据（恢复时先建库） |
| `--no-data` / `--no-create-info` | 只结构 / 只数据 |
| `--where="条件"` | 单表条件导出（配合表名参数） |
| `--set-gtid-purged=OFF` | GTID 库备份文件导入到非 GTID 库报错时加 |
| `--max-allowed-packet=512M` | 超大行 / 大字段报包超限时加 |
| `--login-path=名` | `mysql_config_editor set --login-path=prod --host=… --user=… --password` 存过的混淆凭据路径，命令行干净 |

> RBS 配合：`tool: mysqldump` 绑定 +
> `secret_env: { MYSQL_PWD: db/prod-mysql }`（先 `remote-build set-password db/prod-mysql <密码>`），
> 连接信息走变量组——示范工程 ⑤ 即完整示例。备份文件建议再配 7z 压缩或 upload 拉回发版机归档。

## 十六、PostgreSQL（psql / pg_dump）【本地客户端 → 远程库】

```bash
psql -h ${{ variables.DB_HOST }} -p 5432 -U postgres -d app_db -c "\dt"
psql -h host -U postgres -d app_db -f restore.sql          # 执行 SQL 文件
pg_dump -h ${{ variables.DB_HOST }} -p ${{ variables.DB_PG_PORT }} -U ${{ variables.DB_USER }} \
  -f backup/pg-${{ now.date }}.sql ${{ variables.DB_NAME }}          # 纯 SQL 备份
pg_dump -Fc -f backup/pg.dump ${{ variables.DB_NAME }}     # 自定义压缩格式
pg_restore -h host -U postgres -d app_db backup/pg.dump    # -Fc 格式用它恢复（可 -j 4 并行）
```

- **端口是小写 `-p`**（MySQL 是大写 `-P`，两库连用时最容易踩）
- `-U` 用户；密码走 `PGPASSWORD` 环境变量 = pg **官方推荐**方式 → `secret_env` 注入即可
- `pg_dump`：`-Fc` 自定义格式（压缩 + 支持选择性恢复，配 `pg_restore`）；`-s` 只结构 /
  `-a` 只数据；`-t 表` / `-n schema` 范围导出；纯 SQL 格式（默认）用 psql 导入即可
- `psql -c "SQL"` 单条命令；`\dt` `\d 表名` 元命令要看交互式输出时用

## 附：与 RBS 字段的搭配速记

| 想要 | 用什么 |
|------|--------|
| 命令里的路径 / 主机 / 库名不写死 | `${{ variables.X }}`（变量组）、`${{ targets.名.字段 }}`（目标字段） |
| 重跑秒过已完成步骤 | `creates: 产物路径` |
| 上一步没产出就跳过 | `when: ${{ env.X != '' }}` |
| 版本号传给后续步骤 | `outputs: { VER: '(\S+)$' }` → `${{ env.VER }}` |
| 密码不进命令行 / YAML | `secret_env: { MYSQL_PWD: 键 }` + `remote-build set-password` |
| 命令找不到 / 版本不对 | `tool:` 绑定 + `tools_require` 门禁 |
| 编译慢被超时误杀 | 步骤 `timeout: 1800` |
| 首次部署服务不存在 | `continue_on_error: true`（黄灯不拦） |
| 传了新包才重启 | `notify:` + `handlers:` |
| 服务起没起来 | `wait` 步骤（tcp / http / command） |
