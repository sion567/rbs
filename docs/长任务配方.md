# 长任务配方（fire-and-poll）与备份校验

> 场景：1.5T 数据库备份、数据迁移这类一跑一两小时的远端脚本。
> 对象：`exec` 远程命令是**阻塞挂在 plink 上**的——步骤超时杀掉 plink，
> 远端进程收 SIGHUP 一起死；就算不超时，SSH 连接断一次任务就废。
> 正确姿势：**远端后台跑（nohup）+ 状态文件 + 工具轮询**，SSH 只当"遥控器"。

## 一、远端脚本约定

备份 / 迁移脚本自己写状态文件，三态：`running | success | failed`：

```sh
#!/bin/sh
# /opt/demo/scripts/backup.sh —— 脚本自己维护 status / log / pid 三件
D=/opt/demo/backup
echo running > $D/status
echo $$ > $D/backup.pid

xtrabackup ... > $D/run.log 2>&1 || { echo failed > $D/status; exit 1; }

# ── 备份校验三件套：全过才允许写 success（见 §三）──
f=$D/db-$(date +%F).xbstream
[ -s "$f" ] || { echo failed > $D/status; exit 1; }

echo success > $D/status
```

要点：

- 开跑第一件事写 `running`，**失败路径必须写 `failed`**（fail-fast 的信号源）；
- 日志重定向到文件，别走 stdout（stdout 已经不属于这个进程了）；
- 大库备份用 `xtrabackup` / `mydumper`，比 `mysqldump` 快一个量级；
- 除 nohup 外，`setsid`、`systemd` oneshot 单元也可以，核心只有一个：
  任务生命周期与 SSH 连接解耦。

## 二、build.yaml 侧：起飞 + 轮询两步

```yaml
steps:
  - name: 起飞远端备份（不等待，立即返回）
    command: nohup /opt/demo/scripts/backup.sh > /dev/null 2>&1 & echo started

  - name: 轮询备份状态（failed 立即失败，不烧完超时）
    step_type: wait
    timeout: 7200                      # 按任务最长预期配，防 status 卡 running
    wait:
      mode: command
      interval_seconds: 30             # 长任务 30~60s 一查足够
      fail_exit_code: 2                # 探测退出码 2 = 任务已死
      target: >-
        s=$(cat /opt/demo/backup/status 2>/dev/null || echo running);
        [ "$s" = success ] && exit 0;
        [ "$s" = failed ] && exit 2;
        exit 1
```

探测命令的退出码语义（自己写包装脚本时**明确控制**退出码）：

| 退出码 | 含义 | 工具行为 |
|---|---|---|
| 0 | 就绪（success） | 步骤成功，继续下一步 |
| `fail_exit_code`（如 2） | 任务已死（failed） | **立即失败**，停止轮询 |
| 其他（如 1） | 还没好（running） | 等一个间隔继续查 |

注意：`grep` 出错（文件不存在等）退出码也是 2——**别拿裸 grep 当探测命令**再配
`fail_exit_code: 2`，文件还没生成的头几轮会被误判成致命失败。用上面的包装写法，
或给 grep 换个约定码。

想人工看进度：`plink <目标> "tail -f /opt/demo/backup/run.log"`（工具内嵌"跟随
远端日志"是远期增强，见 TODO）。

## 三、备份校验三件套

备份"跑完了"不等于"备份对了"。脚本收尾自检三条，任一不过就写 `failed`：

1. **文件存在**：`[ -f "$f" ]`
2. **大小 > 0**：`[ -s "$f" ]`（存在且非空一步到位）
3. **头部格式对**（魔数）：zip 是 `PK`、gzip 是 `1f 8b`、xz 是 `fd 37 7a 58 5a`

```sh
[ -s "$f" ] || { echo failed > $D/status; exit 1; }
head -c 2 "$f" | od -An -tx1 | grep -q "1f 8b" || { echo failed > $D/status; exit 1; }
```

这三条与将来 Capistrano 式 releases/current 回滚是配套的：回滚的前提是备份真的
可用，校验不过的备份等于没有备份。

## 四、边界与相关

- **单机不做金丝雀**：单机场景的安全网 = 这份配方（备份可校验）+ `wait` 健康检查
  + 回滚（TODO 的 Capistrano 线）。流量切分那套没有负载均衡就是自欺。
- **SSH 连接硬化**：P1 OpenSSH 传输已把 `ConnectTimeout=10 / ServerAliveInterval=15 /
  BatchMode=yes` 固化进 `openssh.rs::build_ssh_args`；plink 没有 CLI 保活参数，
  由步骤超时兜底。
- `wait` 探测三模式（command / tcp / http）速查见 GUI「？ 变量语法」窗口；
  `fail_exit_code` 仅 command 模式有意义。
